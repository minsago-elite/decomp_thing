## Boundaries and critical decision

`runtime_command` creates a read-only bubblewrap worker and `bounded_run` verifies a systemd cgroup and cleanup. These prevent host access and surviving descendants; they do not separate the native library from `private/caller.c`. `dlopen` runs constructors in the caller, before LOAD_OK. Calls, callbacks, state, stdout, stderr, memory, and inherited file descriptors share that process. The existing stderr strings therefore prove only that bytes were written. Removing these strings also removes candidate behavior bytes. An inherited pipe, socket, eventfd, secret token in caller memory, or a caller-address breakpoint is not an authenticated semantic event channel: the candidate can write the channel, read the token, or redirect execution to the notification code. Merely putting a monitor outside this worker does not repair that fact.

The minimum *authority* required is a component outside candidate-accessible memory and file descriptors that owns both loading and the decision to invoke a specific exported ABI entry. It must record an invocation at the actual machine entry transition, not before a candidate-capable loader/constructor runs, and record completion independently. Candidate-owned return values and bytes remain behavior, not authority. The component must also own callback dispatch and preserve all 24 scenarios, including struct values/returns, mutable exported state, varargs, callback counts/context effects, and cleanup. A separate RPC worker that simply sends `loaded`/`called` messages has the original defect.

There is no such component in the inspected implementation. Do not claim that a pipe or a few ptrace breakpoints implements it. Do not replace exercised-call evidence with permanent unknown results or narrow #1507 to declarations.

A concrete implementation route to qualify is a **bounded x86-64 guest executor with an external loader and fixed ABI bridge**. Candidate machine code and candidate dependencies execute only in guest memory. Loader state, scenario scheduler, events and event descriptors stay in host memory. The host maps validated ELF objects, performs the supported relocations, runs constructors as guest execution, resolves exports from validated loaded images, constructs the five fixed SysV ABI calls, and owns callback trampolines that transfer to the host only through validated bridge operations. Guest calls cannot modify host event records. The executor must support the pinned GCC output and default dynamic closure; unsupported instructions, relocation/library forms, bridge calls, or escapes are explicit unknown/refused, never assumed successful. This is a scoped executor for this fixture ABI, not a universal tracing project. It is nevertheless a new capability, not a small marker-parser patch, and it changes the runtime contract: qualify equivalence on the full scenario corpus before adopting it.

**Unresolved authority gate:** root must select and authorize the bounded runtime capability and its qualified execution environment before native/runtime qualification, a new freeze, or a closure claim. This plan does not assert an existing guest engine is installed or suitable. A debugger solution is acceptable only if it demonstrates an equivalent inaccessible authority boundary, including candidate writes, constructors, threads and control transfers; instruction-address observations alone are insufficient. Existing repository permissions for source planning do not establish that qualification. Root can immediately perform steps 1–5 and the public design/prototype portion of step 6 without a new private/model trial.
