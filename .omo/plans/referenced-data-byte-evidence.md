## Proposed closed contract (review before implementation)

Introduce model schema 3 and exporter identity 12. Add required `byteEvidence` to every schema-3 global, retaining `initializer` unchanged and separate. The evidence object has exact keys `schemaVersion` (1), `windows` and `omissionReason` (null or closed reason enum). Windows have exact keys `address`, `requestedLength`, `origin`, `availability`, `segments`. Origin has exact keys `instructionAddress`, `referenceAddress`, `operandIndex` (nullable), `widthBasis` (`pcode_load`, `pcode_store`, `unknown_width`). Addresses use existing canonical unsigned 64-bit formatting; support only the exporter’s existing memory address-space scope and reject unrepresentable addresses. Reference address is the actual reference target, not the containing listing datum base. No field claims an object extent or a C type.

A known-width window's positive requested length is derived only from an unambiguously associated LOAD output or STORE value size in the referring instruction's p-code. Use public bundled Ghidra Java APIs. Do not infer width from listing data type, initializer string, architecture register size, or adjacent symbols. Ambiguous/dynamic p-code association yields unknown width: requestedLength null, no segments, availability `unknown`, object-level omissionReason `unknown_access_width` as defined below. This is explicit evidence absence, not an empty recovered value. Do not invent a fallback object extent.

The complete object-level `omissionReason` domain is JSON null or `unknown_access_width`; no other string is valid. It is `unknown_access_width` if and only if at least one window has requestedLength null and availability `unknown`. Thus all-known windows require null, mixed known/unknown windows require `unknown_access_width`, and all-unknown windows require `unknown_access_width`. Known-width unavailable/partial windows use segment reasons only and do not independently change omissionReason. Every schema-3 global must have at least one window: an empty windows list is invalid regardless of omissionReason. Every qualifying reference supplies a known-width or unknown-width window; failure to obtain any reference origin for a global is an export integrity error, not an empty evidence object. Historical schemas have no byteEvidence object and are not represented by empty schema-3 windows. Unknown windows must have no segments; known-width windows must have nonempty segments covering their complete requested span.

Segments cover known-width windows in address order without gaps/overlap. Each has exact keys `offset`, `length`, `availability`, `hex`, `reason`. Available segments contain exactly length*2 lowercase hex characters in ascending address order, reason null. Unavailable segments have hex null and reason `unmapped`, `unreadable`, `uninitialized`, or `read_failed`; never zero-fill. Window availability is `available`, `partial`, or `unavailable` according to coverage; `unknown` is reserved for unknown width. Adjacent equal unavailable reasons coalesce. Partial data keeps actual bytes and explicit missing ranges. No segment crosses the requested span or wraps address arithmetic. An all-zero available value remains valid evidence.

Bounds are fixed contract constants shared by implementations/tests: 256 requested bytes/window, 32 windows/global, 64 KiB total requested window bytes/model, 4096 windows/model, and 65536 inspected data-reference candidates/model. Count requested bytes including unreadable spans and duplicate occurrence work, using checked arithmetic before reading/allocation. Known-width over-limit requests produce no truncated window: fail export explicitly with a named bound diagnostic before publishing a completed state; the same rule applies to window/reference/work/global aggregate overflow. Unknown-width records are bounded by candidate/window counts. Read in runs no larger than remaining per-window budget; check cancellation/deadline in scans and reads. Preserve existing stricter record, token, depth, artifact and total-input limits. Prompt byte budget: 64 KiB decoded bytes/module and 512 KiB rendered byte-evidence text/module; fail rendering explicitly before agent invocation if exceeded. These constants are conservative initial safety bounds, not claims of completeness.

Stable ordering: globals retain existing identity; windows sort by address then origin fields and width; exact duplicate windows deduplicate deterministically. Gather complete bounded reference evidence before writing any first-owner global record. Implement a bounded deterministic reference prepass with an index keyed by existing global ID, then render identical global records in planning and full modes. This avoids first encountered instruction or batch order silently choosing a shorter window. Count prepass work even when deduplication removes output. P-code association must distinguish multiple memory operations; inability to do so produces unknown evidence. Byte evidence remains non-authoritative recovered binary input; do not elevate extractionStatus, recoveryAssessment, oracle, ABI, scoring or release authority.
