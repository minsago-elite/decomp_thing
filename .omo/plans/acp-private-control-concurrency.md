## Design: coherent registry transactions with bounded scope leases

Use the existing registry monitor for short metadata transactions. Keep hashing, file copying, process launch, callback bodies, process waits and whole invocations outside it. Do not hold this monitor across invocation execution or scope lifetime. Preserve mount-event polling and full mountinfo equality at finish.

1. Introduce a private registry record per control with an unforgeable object identity, immutable admitted identity/location, and lifecycle LIVE or PROVED_DELETED. Publication, transition and epoch updates occur under the registry monitor. A failed cleanup stays LIVE and protected, retaining existing failure provenance; attempted cleanup is never deletion proof. Retain state records only through live registry membership or bounded scope references. Do not identify records solely by inode, path, epoch number or a reused descriptor integer.
2. A scope owns an independently opened root descriptor, admitted root physical coordinates, mount event descriptor and bounded map from record identity to retained ManifestControlIdentity. Opening/admitting the root, checking all live controls, snapshot creation and publication of its root lease form one registry transaction. Pin and authenticate file roots as well as directory roots. Partial-open failure closes all owned descriptors and removes any published lease before returning.
3. Register active manifest root leases in a bounded registry, separate from host staging roots because runtime source roots may contain nested mounts and need different coverage. Creation admission checks these leases before mkdir. A new control's candidate namespace path and physical filesystem coordinates may not lie within any scope's recursive root, alias of that root, or overlap it as a protected ancestor. Inspect both admitted and authenticated current root coordinates. Allow disjoint sibling controls. No owner exception permits a *new* control to overlap an existing scope; existing private snapshot owner exemption remains limited to its exact admitted control record. Keep existing active-host-staging and private-control overlap rules.
4. Each checkpoint enters the registry monitor, runs cancellation and sticky mount-event checks, reconciles scope membership when registry epoch differs, validates all retained LIVE identities, then returns. Reconciliation drops an old identity only if that exact record is PROVED_DELETED; any other missing LIVE record is corruption and fails closed. For new LIVE records, retain and validate identities using the scope's original mount table; reject overlap with the scope root. Additions/removals commit as a single map replacement; failures close newly retained descriptors and leave the old map owned until scope close. Bound this temporary duplication explicitly. Recompute the fast-path predicate over the complete new live set; never preserve `fast=true` after adding a cross-mount alias. Even without epoch drift, keep per-control mode/key/mount/path validation at every checkpoint.
5. Successful delete holds the registry monitor through the existing descriptor-bound contents drain, quarantine rename, exact rmdir and link-count/name-absence proof. Only after all proofs mark the record PROVED_DELETED and remove it from active membership, then advance epoch. Original descriptors can close after proof; retained manifest descriptors remain scope-owned until reconciliation/close. Checkpoint cannot inspect the intermediate quarantine/unlink state because deletion and validation use the same monitor. A failed rename/replacement/mode/cleanup leaves the record LIVE, so peers continue to fail closed on its unverified identity. Preserve prior failure classification even if later remediation deletes the exact original.
6. Creation remains atomic under the registry monitor from pre-mkdir exclusion to publication. Preserve pre-creation epoch invalidation as a transaction change indicator; allow peers to reconcile it only after the transaction exits. If partial creation cannot pin or prove removal, publish bounded poisoned registry state (or an equivalent sticky fail-closed guard) rather than letting epoch reconciliation silently accept an unresolved private directory. Registry poison prevents subsequent manifest/authority admission until exact remediation is proven; it must carry no raw secret/path diagnostic. Proven clean creation failure is harmless peer churn.
7. Scope `requireDescriptor` must observe one coherent exclusion set for its descriptor check: use a registry-locked helper covering reconcile, identity validation and overlap decision. Keep no gap in which code consults a mutable map outside that lock. Existing before/after checkpoints around filesystem reads still detect mounts/control drift; do not use a concurrent collection as a substitute for the transaction. The slow physical-coordinate branch remains for bind aliases. Preserve admitted/current control locations, descriptor identity, no-symlink reopening, mode checks, exact mount IDs, recursive ancestor denial and owner scoping.
8. Close unregisters the root lease and detaches owned descriptors under the registry monitor; close each descriptor exactly once. Scope close must remain reliable after cancellation/failure and cannot use the cancelled callback to skip release. Define lock order registry -> descriptor and remove the current method-monitor -> registry inversion in deleteAndProve (`@Synchronized`) if it can conflict with new helpers. No registry operation acquires a per-control monitor. No asynchronous deletion/tombstone collector is required.

### Mount and lifetime argument

Registry epoch is a change notification, not security proof and not a substitute for mount events. Mount mutations, including mount/unmount restoration with equal final mountinfo, remain fatal through the existing independently retained event descriptor. Read it once at scope open; never acknowledge and ignore a poll event. Preserve finish's full mount table comparison. Root admission and control registration compare physical coordinates using exact mount IDs and authenticated no-follow descriptor paths, including mount roots and bind aliases. A nested bind below a runtime root must not conceal an overlapping candidate from registration admission: compare against every mounted subtree reachable beneath that recursive root, translated through the original mount table, in addition to the root's own filesystem coordinates. Reuse a shared physical-coverage helper for initial scope admission and new-control admission; do not assume root filesystem equality covers descendant filesystems. If coverage cannot be authenticated, deny the registration/scope.

Snapshot descriptors pin original inodes across deletion, preventing ABA reuse until release. Record identity distinguishes a later same-path registration even when keys could eventually recycle. A proved deleted record can be dropped because its directory is proven empty/unlinked and future control publication must pass the active root leases. A hostile rename or replacement lacks that transition and still fails. A LIVE record which moves away and back between checkpoints retains existing detection limits; this fix must not claim to solve arbitrary undetectable host writes or weaken the existing per-check identity/mount guarantees. Epoch equality uses equality only, with a nonreused change token or checked overflow failure; wraparound cannot restore an earlier accepted state.

### Resource bounds

Keep 128 active controls and 128 active host staging roots. Add an explicit 128 active manifest scope ceiling, with typed/consistent bounded admission failure before FD allocation. Each scope retains at most 128 control descriptors + one root + one mount descriptor. A transactional refresh may transiently own at most 128 additional descriptors; prefer retaining unchanged entries and opening only new records. Total persistent manifest descriptors <= 16,640, plus existing registry/staging ownership; temporary refresh <=128 per registry transaction. This is an upper bound, not an OS-FD availability guarantee: preserve allocation failure cleanup, caller budgets and low-RLIMIT failure tests. Retired records do not accumulate with churn; each scope retains at most its previous bounded snapshot until next checkpoint/close. Do not impose the native child's 128 FD policy on host registry accounting or imply this bound proves production resource admission. Reassess a lower scope ceiling if the application host FD budget requires it; document the chosen value and test it. Bound poisoning/failed-creation records within admission capacity so failures cannot create an unbounded side list.
