# Retained input visibility

A contained command may select a strict view of an already owned run lease with `retainedInputVisibility`. Null preserves existing requests and mounts. An empty list hides every prior file. A nonempty list allows only canonical relative files beneath already pinned protected directories; paths cannot enter the active control.

The strict child view starts as an empty read-only mount. Bounded parent directories are created, the active control is separately bound writable on the original quota-controlled filesystem, and selected prior files are bound read-only. Prior controls, model reports, state and untracked siblings are absent. Parent mount topology and whole-lease accounting/cleanup remain unchanged; no writable overlay can hold unaccounted data.

Selections are immutable, limited to64 files, depth4,128 parents and128MiB aggregate (64MiB per file). Private directory/regular single-link file checks and held descriptor hash/identity guards reject aliases and substitutions. The launcher rechecks all sources around START and after verified absence, ending with a callback-free whole-set metadata pass.

The canonical visibility document enters the runtime closure, and its digest enters contained request v4 and therefore authenticated BOOT/START/outcome and attachment/execution lineage. Requests v1/v2 remain byte-compatible when visibility is null. Request v3 retains the separate terminal-resource contract, including omitted false interruption and strict authenticated pipe hashes; v4 requires an explicit interruption Boolean and retains the original event-wire format. The shared codec supports both existing contracts, with distinct named policy fields. Selecting terminal evidence and a non-null visibility view together is rejected before launcher preparation, including an empty view. The existing runtime/provider field sets and default resource policy remain unchanged; this composition does not add an FD policy or combined mode.

Focused controls exercise limits, null compatibility, request authentication, source substitutions and actual generated bubblewrap arguments. The actual child reads exactly its allowed files, cannot modify them or write the empty root, cannot read hidden siblings, and writes only the active control. These authored controls establish the namespace mechanism; a production adapter still needs its actual contained execution and retained input/capture lineage.
