# Untrusted web content boundary

This document records the focused implementation boundary for issue #519. It does
not qualify the production CSP or the complete D10 release gate owned by #518 and
#176.

## Rendering contract

Uploaded names, retained report strings, source text, diagnostic labels and agent
observations are data, never application markup.

- Preact views use JSX text children. They do not use `innerHTML`,
  `dangerouslySetInnerHTML`, a Markdown renderer or a generated-content iframe.
- The versioned client accepts server-supplied resource links only when they are
  the exact root-relative route for the expected job, attempt and artifact under
  the configured application base path. Absolute, scheme-relative, `javascript:`,
  `data:`, `blob:`, backslash and encoded-origin alternatives fail closed.
- Legacy HTML escapes every retained string before placing it in text or an
  attribute. Report source labels are mapped to a fixed CSS-class vocabulary;
  count/progress values and repair iteration labels do not bypass escaping.
- Legacy live progress creates DOM elements itself and assigns retained values
  through `textContent`. Message, plan and tool prose remains withheld because the
  journal does not certify it for public display.
- Source files are shown only as escaped text inside `pre`/`code`. There is no
  HTML, SVG or Markdown preview mode.

The page renderer still owns reviewed application markup and scripts. Removing
legacy inline application script/style requirements and enforcing the production
page policy belongs to #518; this boundary only prevents retained/generated bytes
from becoming that trusted markup.

## Download contract

Legacy artifact and verified source-archive responses are attachments. Their
fallback filenames contain only bounded ASCII letters, digits, dot, underscore
and hyphen; the original filename is carried only as percent-encoded RFC 5987
metadata. Every response applies `nosniff`, `no-referrer`, and an attachment CSP
of `sandbox; default-src 'none'; base-uri 'none'; form-action 'none'`.

Known JSON and plain-text extensions keep useful declared media types, while HTML,
SVG, JavaScript, XML and unknown extensions are served as
`application/octet-stream`. Attachment disposition, sandboxing and `nosniff` are
independent controls: a browser that renders generated bytes despite the download
disposition still receives no application-origin script, form or base authority.
The versioned exploration-artifact endpoint already uses the same fail-closed
shape: authenticated exact identity, octet-stream attachment, `nosniff` and a
sandboxed no-source policy.

## Focused verification

`UploadServerTest` supplies harmless active-markup canaries through filenames,
diagnostics, report metrics, candidate sources, repair history, reconstruction
progress, source text and HTML/SVG/Markdown artifacts. It checks escaped legacy
output, fixed CSS class selection, unchanged download bytes, fail-closed media
typing, sandbox policy, `nosniff`, `no-referrer`, and safe content-disposition
metadata. Existing progress tests verify private message text is withheld and
browser updates use text nodes.

Frontend activity tests additionally place an HTML event-handler canary in the
retained writer, phase, status, task and revision fields. The canary remains text,
creates no image or event-handler node, and produces no link beyond the validated
same-application attempt route. Path/contract tests reject alternate schemes,
origins, prefixes and identities.

These deterministic fixtures use no native analyzer, compiler binary, model
credential or external origin. Full packaged-browser CSP violation collection,
source highlighting and production asset policy qualification remain #518 scope;
cross-browser and release qualification remain under #176, D11 and D12.
