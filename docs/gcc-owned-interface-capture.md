# Owned GCC driver interface observations

Issue #1756 adds a fresh, pinned-driver recovery route for the raw listing and inferred interface components. It does not admit the INTERFACES structural domain, infer source parameter cardinality, normalize ABI equivalence, or score any interface threshold. Issues #679, #680, #692 and #693 retain those independent obligations.

`gcc-engine-interface-observations driver <stripped-binary> --profile <exporter17-profile> --ghidra-archive <archive> --output <private-output> --scratch <qualified-scratch>` selects bundled Java API invocation 9. The command admits only the independently retained driver target; cc1, lto1, diagnostics, planning, native-call capture, interruption and resume are separate routes. Ordinary full-export execution/publication accepts only existing invocation 5/6. No `GHIDRA_HOME` or external `analyzeHeadless` process is used.

The selected deployment commits the exact model/listing/inferred/type-graph/wrapper sources, all owned class families including nested helper classes, the bridge JAR, compiled wrapper, native decompiler, ordered runtime classpath and BOOT/runtime references. These deployment commitments are distinct from the raw collectors' source bindings. The fixed worker argument envelope is validated before Ghidra initialization. Existing absent-interface deployment references retain their old representation.

Execution retains the driver's existing 1,800-second operation budget, 16-GiB memory limit and 128-PID ceiling, with a serial 2-GiB Java heap. The inferred collector uses one existing 120-second lifetime and its existing clipped per-function limits; there is no per-function budget reset or partial successful truncation. The reports directory must be wholly empty at both START checks. Before Ghidra initialization, invocation9 performs a fixed probe of six host-only role canaries and the actual rich-binary sibling, verifies both selected inputs are readable on read-only filesystem views, and requires noncreating/nontruncating WRITE opens to fail. Only fixed outcomes and the selected input digest are emitted in one bounded stderr frame; the probe accepts no caller-supplied paths or switches. Selected binary and exporter inputs are read-only and the synthetic worker root exposes no oracle/source/build tree.

After worker, unit, cgroup and process absence is established, the capture owns and revalidates the full model tree, state/progress, both listing/inferred sidecars and manifests, and the two bounded worker streams. Stream content hashes enter the owned assessment; their byte counts must also equal the authenticated worker outcome. Byte counts alone do not authenticate a containment probe frame. A single 1-GiB aggregate accounts for retained capture bytes and publication metadata. Captures preserve every observed native function, every model function, nine inferred dispositions, explicit unavailable/ambiguous mapping states, and the raw type graph. Independent target metadata fixes the address-space descriptor before the observed index is accepted. Listing and inferred records remain separate recovery observations.

Construction of `GccBundledInterfaceOperation` does not confer ownership. The fully checked live factory registers an owner, consumes a one-use private pending token after final descriptor validation, and registers the exact completed result identity. Evidence access checks both result membership and its live completed owner. Failed execution cannot expose a usable result, and proven cleanup followed by closure revokes owner and result membership. Archived JSON and reconstructed objects cannot acquire that live identity.

The CLI publishes a recovery binding and result marker only after rechecking the complete captured tree and receipt lineage. `completeObservedNativeCensus=true` describes the observed recovery population; `complete`, `authoritativeOracleEvidence`, `productionInterfacesAdmitted`, `scored` and `releaseEligible` remain false. Durable replay can validate preserved bytes and their commitments, but cannot recreate live ownership or ABI truth.

## Explicit installed qualification

The manual `driver-interface-observations` operation in `gcc-oracle-model.yml` selects the existing contained driver workflow with the serial exporter17 profile. No pull-request label automatically starts this expensive lane. `ci-qualify-gcc-cc1-full-export.sh driver-interface-observations` enables one exact opt-in method, rejects an old XML result, forces fresh test execution, and uses a bounded inventory verifier to require that method once with zero failures/errors/skips. A successful Gradle exit without the exact XML inventory is insufficient.

The qualification pins host-only canaries and the actual rich sibling before execution, checks that they remain unchanged, and compares the fixed probe to the exact owned stderr bytes. It reconstructs the installed deployment and operation intent, preserves BOOT/START/OUTCOME and linked receipts, checks unchanged operation/resource limits and worker absence, copies every captured file and empty directory under the same aggregate, and replays both raw readers twice. Recorded HMACs cannot be reauthenticated after the live secret is destroyed; archived commitments never reconstruct factory membership. Canary observations corroborate the fixed empty-root/input-mount policy and do not prove invisibility of every possible host path by themselves.

A failed worker or collector lifetime retains bounded stdout/stderr diagnostic prefixes and failed execution inventory. A missing result is never turned into a successful partial capture. The one actual driver feasibility run remains pending until the complete implementation and controls are frozen and independently reviewed.
