# Recovered ABI interface candidate projection v1

`RecoveredAbiInterfaceCandidateProjectionV1` is a deterministic, bounded projection from separately validated native listing and HighFunction observations into structural fact-shaped **candidates**. The result is caller-supplied/untrusted data. It is not a validation receipt, oracle observation, score, production replay, or `INTERFACES` admission grant. The typed records and their digest fields are public DTOs; the projection labels stream digests as claims because it does not reopen and authenticate the original report bytes.

The model-to-native identity comes only from the listing assessment's unique matched entry mapping. The projection retains every model function as an entity and every native listing function not consumed by a unique match in a separate `nativeOnlyFunctions` partition. It recomputes candidate sets, mapping states, and paired external/thunk flags from the supplied typed rows, then checks the complete listing and inference scan totals. Listing parameter ordinals and HighFunction parameter indices, category indices, and high slots remain separate raw channels; there is no positional join between them.

The only currently recoverable candidate dimensions are:

- `function.calling-convention`: known only when the raw convention state is `named-resolved`, both its raw name and resolved model alias resolve to the same entry in the supplied target descriptor, and the function is uniquely mapped and not a thunk.
- `function.variadic`: known only when the HighFunction observation completed validly, its formal/local counts agree, and its `varArgs` bit agrees with the listing bit on a uniquely mapped non-thunk function.
- `function.return-abi-class` and `function.parameter-abi-class`: a candidate is emitted only for a uniquely matched, ordinary function with no custom storage, forced-indirect role, or automatic parameter role, and only from its exact `return-formal` or `parameter-formal` listing graph root. The listing validator joins that root to the exact formal datatype occurrence and ordinal; this does not join listing parameters to HighFunction positions. A capture-local `type-token:<sha256>` names the root occurrence for the candidate and does not claim canonical source-type identity. The complete root graph must have a supported layout and the target/data organization must match the explicitly supported SysV AMD64 ELF LP64 profile. The classifier reuses the closed `DwarfSysvAmd64Classification` algorithm. Missing, incomplete, ambiguous, unsupported, custom-storage, forced-indirect, automatic `this`, and hidden-role cases remain `recovered-unknown`.
- `function.prototype` remains `recovered-unknown`: the capture does not establish a canonical recovered source signature. The HighFunction stream declares its formal/effective relation unavailable, so its type roots are retained separately and are not joined to listing slots. Listing formal roots may still produce ABI class candidates because their own exact ordinal/role relationship is validated. The separate listing and inference payloads retain raw fields, including the return type ordinal and each HighFunction parameter's explicit hidden-return flag. A return type's presence never stands in for the `isHiddenReturn` flag.

The target descriptor is parsed and structurally validated by the existing loader, but that DTO is not an authenticated production capability. The projection never receives oracle visibility controls and never classifies absent candidates as oracle-unobservable. These candidates cannot establish unknown/unsupported oracle partitions or conservation required by the scorer. Any future scoring path must separately validate source bytes and join candidates with trusted oracle evidence under its own admission boundary.

`projectCapturedSnapshot` revalidates the retained report bytes and their bindings before collecting typed candidate rows. It refuses candidate materialization above 128 MiB across model/listing/inference inputs. The DTO-taking `project` overload remains untrusted and does not authenticate its digest claims. The projection bounds input record counts, per-function and total parameter counts, mapping references, per-storage and aggregate varnodes, cumulative UTF-8 field bytes, nested type-detail JSON nodes and traversal queue, graph nodes/edges/work, conservative serialized size, and final canonical output size. It checkpoints across record and nested-detail traversal. Failure returns no partial projection.
