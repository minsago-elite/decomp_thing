# Owned native and external call replay

The selected `gcc-engine-native-calls driver` route freezes the complete native core population and recovered external candidates before opening the structural profile or oracle. The coordinator retains the original manifest, raw stream, model, every record/site ordinal, and both recovery-only derivations. A second held-descriptor read re-freezes the original sources before external replay; saved JSON bindings cannot replace those bytes.

After the selected boundary replay and independent machine producer, two fixed bundled workers run sequentially. The independent external worker receives the original machine report/request and rich ELF. The recovered external worker receives only the original native manifest/stream and pinned artifact manifest/rich/stripped pair. The held ELF pair checks exact dynamic metadata and instruction-byte correspondence without naming or oracle-target fallback. The host validates the full recovered component after raw-source re-freeze; request commitments alone are insufficient.

Each producer gets a strict child view of the existing lease. The machine producer sees no prior files, independent external replay sees only its captured machine report, and recovered external replay sees only the native manifest and stream. All other prior controls, state, reports, models and untracked siblings are hidden. An empty read-only mount contains bounded parent directories; the active control is a separate writable bind on the original quota-controlled filesystem. Selected prior files are private, single-link, descriptor-pinned read-only binds. The whole original lease remains subject to the same accounting and cleanup. Visibility is committed in request v4 and the runtime closure; unrelated request v3 remains reserved for terminal-resource evidence. Null visibility preserves legacy v1/v2 requests and mount behavior.

The combined operation can be created only with the live coordinator's private permit and its genuine guarded predecessor. Original worker requests, attachments, executions, absence proofs, captures and outputs are retained. The result marker is published after final input/output checks. Both workers share the remaining parent deadline and existing resident-memory, PID, file and filesystem budgets; no phase resets a deadline or increases a resource ceiling.

The result's v3 native pointers bind the independent and recovered external reports, exact namespace/pair, deterministic call ledger input/report and source composition evidence. The existing native/model/function evidence remains retained. Every raw call ordinal is disposed once. Only an exact selected owner exclusion removes a call from the ledger; a target exclusion cannot remove its caller. The same physical call and its semantic external target receive one obligation. Indirect calls remain indirect, conflicting or missing targets remain unknown, and candidate tokens on unresolved independent rows receive no positive credit.

These artifacts do not grant the CALLS registry domain, negative coverage, a complete call population, an accuracy threshold or full release eligibility. The pure ledger's flags remain false. Actual hosted qualification must retain the exact source/run and full chain, re-freeze/rederive twice, and report whether a real positive recovered external witness occurred. Deterministic replay of fixed bytes is distinct from rerunning the native producer. Local authored fixtures and namespace canaries are implementation controls, not production qualification.
