# Native listing-interface observations v1

This component records the bundled Ghidra listing database through typed Java APIs. It is recovered observation data, not an ABI oracle, a production capability or an accuracy report. It implements the observation foundation in #1737; #680 and its complete production replay requirements remain open.

`ExportNativeInterfacesV1` runs as a fixed compiled collector in the existing isolated bundled worker. It does not invoke decompilation, load source truth, parse prototype display strings, change the program model exporter or require an installed Ghidra. Its inputs are the current `Program`, cancellation monitor, input SHA, model exporter SHA, bundled archive SHA, collector SHA, frozen model path and fresh output directory. The supplied identities become byte commitments; they do not authenticate the caller. Future production orchestration must bind the genuine worker/runtime and freeze the exact paired model before independent oracle replay.

## Retained observation population

Every currently listed internal and external function has a record. Immediate thunk targets remain explicit, including thunk chains. A complete listing census is not a claim that all binary functions were recovered. The collector checks native counts and preserves empty/default signatures without interpreting them as independently proven zero arity.

Each function retains its typed entry address, signature source, calling convention name and resolved model state, variadic/custom-storage flags, return parameter and ordered parameter list. Each parameter retains its native ordinal, source, automatic kind, forced-indirect state, formal datatype and effective datatype separately. Thus hidden return parameters, implicit `this`, and formal aggregates represented by effective pointers cannot be silently replaced by display declarations.

The raw `autoParameterCount` getter and each parameter's automatic flag are retained independently. Ghidra 12.1.3 thunk getters can disagree with those flags; `autoParameterCountMatchesObserved` exposes the discrepancy, and the summary counts observed automatic flags. Neither source field is overwritten. Such a discrepancy needs explicit handling before future ABI normalization.

Storage retains native size and ordered typed varnodes, including register/stack mixtures and compound pieces. BAD, UNASSIGNED, VOID and absent storage remain distinct. Unsupported datatype kinds remain `other` with their native class and metadata. There is no inferred ABI class, passing mode, alignment rule, source identity or normalized argument count. Metadata that cannot be read within the fixed contract fails the whole capture instead of publishing a partial population.

Type ordinals are dense **root occurrence references**, in function order, then return formal/effective and parameter formal/effective order. Repeated occurrences deliberately have different ordinals. These references assert neither type equality nor graph closure. Only immediate native kind, class, name/path, length, aligned length, alignment, integer signedness, undefined and not-yet-defined flags are recorded. Aggregate members, pointer targets, aliases and ABI layouts are not traversed. Type layout and closure remain `not-captured`.

HighFunction inference is explicitly `not-captured` for every function and for the document. Listing parameter ordinals cannot be treated as HighSymbol slot identities. The existing C-only export does not provide those facts.

## Bytes, identities and bounds

The closed manifest commits to the exact native observation bytes and the frozen model hash. The document also binds model size, input, exporter, collector, bundled archive, language/compiler specification and image base. Addresses use the existing native wire encoding: `{kind: "address", spaceIndex, offsetBits}` or `{kind: "no-address"}`. The address-space inventory retains width, addressable unit size, signed-offset semantics and overlay state. Sixteen hexadecimal offset bits are native offsets, not normalized RVAs.

The collector and Kotlin reader enforce fixed limits: 1 GiB combined observation/manifest bytes, 64 KiB manifest, 512 MiB model, 131,072 functions, 1,024 parameters per function, 1,000,000 total parameters, 524,288 type occurrences, 64 pieces per storage, 1,000,000 storage pieces, 256 address spaces, 1 MiB per record and 4,096 UTF-8 bytes per metadata string. Kotlin adds bounded depth, tokens and per-record nodes. The separate paired-model parser uses explicit full-export-compatible bounds: scalar limits of 64 × 1024 × 1024 code points, one million references per function and 131,072 model globals/types; scalar/reference and aggregate string/node/token bounds are tightened by the configured model-byte cap. The native metadata limit does not impose historical scorer text/prototype limits on a genuine full model. These parsing allowances do not prove that a caller-authored model passed the separate full-export capture boundary. JSON schemas describe the closed wire shape; executable checks also enforce byte limits, order, dense references, storage totals and population conservation. Schemas' string character bounds do not replace the stricter UTF-8 byte limits.

Type rows are spooled under the owned output staging directory, with a digest checked while copying them into final output. Frozen model identity is checked before and after collection. The native Program modification number is also checked before publication, so changing a signature or name without changing the function count still invalidates capture. Cancellation or consistency failure leaves no successful manifest. All record callbacks from the streaming reader are speculative until successful validation returns.

`NativeInterfaceObservationsV1` validates exact frozen canonical model bytes and returns both complete coordinate universes. Every model function remains matched, ambiguous or missing from the listing. Every observed function remains matched, ambiguous, external-unmapped, in a different address space, or unmatched. The model exports scalar offsets without native space IDs. Projection therefore retains each raw model offset and every candidate native entry; it only matches a unique candidate in the bound base memory space. Cross-space collisions remain ambiguous, off-space candidates remain explicit, and no typed coordinate is invented for a missing model function. Names never select identities; duplicate model addresses retain every model ID as ambiguous. External functions, thunks, overlays and unmatched records cannot disappear because the existing model exporter omits them.

The returned summary is an ordinary byte assessment. Its oracle, scored, production-interface-admitted and release-eligible flags are always false. Even a self-consistent authored document has no live provenance authority.

The [pinned API source census](native-interface-observations-v1-api-sources.json) records bundled source-archive and entry hashes, line locators, and authored compiler-profile hashes for independent review. It includes the raw thunk auto-count behavior and datatype/storage API distinctions. These locators establish which API was inspected, not production provenance.

## Verification and remaining production gates

Authored Kotlin controls cover exact commitments, complete model/native universes, ambiguous coordinates, unknown/absent states, ordered storage, dense formal/effective references, closed fields, schemas, limits and cancellation. A bounded fresh JVM control uses the actual pinned Ghidra APIs and an authored Windows x86-64 `ProgramDB`, including forced-indirect aggregates, hidden return and `this`, mixed register/stack arguments, compound storage, variadic/default/undefined signatures, external functions and immediate thunk chains. It compares each observed field against native objects, checks repeat determinism, and verifies that collection leaves both the program and frozen model unchanged. These are component controls, not evidence of production ABI accuracy.

Still required for #680: genuine contained selected-driver sibling capture bound to the exact recovery freeze; independently authenticated DWARF/source projection after recovery; reviewed normalization of five interface dimensions; complete parameter and function obligations even when arity/location is unknown; independent absence/negative authority; selected-boundary projection without duplicate models; a genuine registry-scoped INTERFACES admission; and retained deterministic production replay/qualification evidence. ABI-equivalence needs independent representation and proof of passing conventions; size/class/alignment coincidences do not establish it. Unknown, unsupported and unobservable records cannot count as correct or vanish from denominators. #692, #693 and #1513 retain their full population, threshold and source-ownership obligations.
