# Passive harness readiness reads

Authenticated bootstrap reads the projector's immutable cached observation through `snapshot()`. This read takes no projector monitor, submits no task, loads no harness configuration, constructs no adapter and invokes no sandbox or provider probe. A missing, expired or future-dated observation reports fixed `unavailable` / `READINESS_UNVERIFIED` metadata. A closed projector reports the existing fixed failure state. Capability metadata grants no workflow authority; advertised workflows and limits retain their existing unavailable projection.

The active `current()` refresh remains separate. Bootstrap does not call it, and this change exposes no refresh route or background refresh. Explicit diagnostic admission and shared doctor/harness service integration still require their full contracts. The existing active refresh deadline, abandonment guard and execution implementation are unchanged. An immutable observation bundles its result and captured monotonic refresh coordinate so passive readers cannot pair values from different refreshes.

Three callback-only tests use injected results and clocks. They check that empty, expired and closed reads do not invoke the probe, that only explicit refresh publishes results, and that a passive read does not wait for the active refresh monitor. They run no HTTP server, analyzed binary, actual sandbox helper, provider, ACP agent, doctor command or configuration loader. The original eight readiness tests and all existing controller/native test files remain unchanged from the current canonical source.

The full readiness outcome remains open: configured/unsupported/not-ready classification, complete Ghidra/helper/model-agent coverage, bounded cancellation/staleness and shared doctor/harness services require their original scope and qualification. This correction separates passive reads from active authority. It does not prove positive provider readiness, workflow execution, historical native failure causes or cleanup, or completion of the broader readiness milestone.

The integration preserves the current canonical bundled-Ghidra presence callback and its original eight readiness tests byte for byte. That active diagnostic implementation is separate from passive bootstrap authority; no positive readiness or bundle validation follows from the passive snapshot.
