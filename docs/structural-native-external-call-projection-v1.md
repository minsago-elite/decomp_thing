# Native external call population projection

`StructuralNativeExternalCallProjectionV1` is a pure adapter into the existing closed `StructuralCallPopulationV1` ledger. It accepts both original native freezes, an exact selected boundary projection, the original independent machine report, independently validated external reports, and the expected complete object-local namespace. It cannot issue a production capability.

The original raw streams are the two denominator sources. Derived external reports refine those source ordinals; they do not add populations. Every native site maps once to an obligation or an exact ignored-owner exclusion; non-site native records remain in the original complete freeze census. Every independent machine ordinal also appears exactly once. Reordered, omitted, duplicate or substituted source references fail validation. Source bytes, upstream policy hashes, composition policy, namespace and output commitments are retained.

Only a supported `verified-object-local-import-request` recovery disposition can refine an existing physical own-target claim. The independent side requires both supported composition and target-binding dispositions; a non-null candidate token is insufficient. External request tokens identify static object-local imports, not runtime providers or implementations. Physical indirect calls remain indirect. Nonphysical observations, absent targets, unowned/unmapped sites and conflicting external nodes remain explicit unknowns.

Duplicate physical witnesses consolidate their original references once. Disagreement removes concrete target credit. Independent owner exclusions retain the exact selected exclusion row; excluded targets alone never remove an obligation. Positive-only source coverage is explicit, with additional gaps for unsupported canonical extents. Missing negative coverage cannot turn an unmatched recovered observation into a fabricated call.

The adapter derives the unchanged ledger deterministically and retains separate composition evidence. Parsing, authored test witnesses, rehashed reports and archived outputs remain nonauthoritative. Production callers must separately prove runtime execution, guarded captures, held paired inputs and complete raw-source re-freeze. Input32MiB, report64MiB, combined100,000 call records/sites and existing JSON limits are hard bounds; exceeding them fails without truncation.
