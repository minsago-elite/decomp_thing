# Referenced data byte evidence

Program-model schema 4 and exporter 13 preserve bounded raw referenced input windows and explicit collection omissions separately from listing initializer display text. These windows carry no object extent, C type, initializer, oracle, ABI, scoring or release authority. Schema 3/exporter 12 remains a distinct historical generation.

Every schema-4 global has a required `byteEvidence` key: null means evidence was not supplied and completeness is unknown; an object must use evidence version 2. The bundled exporter emits globals only for eligible data references and requires supplied evidence for every such global. String-only references retain the existing strings relation without fabricated data globals. A window identifies the actual reference target address and instruction/reference/operand origin. A positive `requestedLength` comes only from one unambiguous statically associated access in an instruction's raw p-code. The finite supported policy is:

- LOAD output or STORE value size, when the constant pointer and address-space ID exactly match the reference target.
- COPY direct RAM input or output size, when its single input and output sizes agree and the memory address and space exactly match the target.
- FLOAT_ADD or FLOAT_MULT direct RAM value-input size, for a two-input operation with a nonnull output and equal input/output sizes. Either value input can match the exact target address and space; an output aliasing that target is rejected.

Direct reads use the existing `pcode_direct_read` basis and COPY writes use `pcode_direct_write`. More than one matching association, inconsistent sizes, dynamic pointers, or target memory operands in unreviewed opcodes remain unknown. Control-flow destinations do not establish data-read widths. This policy does not infer an object extent, a C type or a full initializer from the access size. An unknown association has null length, `unknown` availability, no segments and `unknown_width` basis. `omissionReason` is `unknown_access_width` exactly when any window has unknown width, otherwise null.

Known windows contain contiguous offset/length segments covering the complete requested span. Available segments carry lowercase address-order hex; unavailable segments carry null hex and an explicit `unmapped`, `unreadable`, `uninitialized` or `read_failed` reason. Available zero bytes remain data. Missing bytes are never filled or silently truncated. Window availability summarizes complete, partial or absent coverage.

The exporter gathers references before publishing first-owner global records. Function/instruction traversal is stable; references within each bounded instruction batch are sorted before admission. Windows sort by target and origin. Duplicate origins collapse before payload charges; conflicting metadata for the same target/instruction/operand refuses. Duplicate visits still consume reference work. Planning and full exports share rendering. Exact global records, including omission metadata, enter semantic and capture commitments, so local record edits cannot retain an earlier authenticated state.

Limits remain 256 requested bytes/window, 32 retained windows/global, 65,536 requested bytes/model, 4,096 retained windows/model and 65,536 admitted raw memory-reference entries/model. Requested bytes include unavailable spans; only newly retained origins consume window/byte payload budgets. Raw reference work is charged before filtering and includes duplicates. A whole instruction batch that exceeds remaining reference work is not admitted; one nonretained lookahead detects overflow without width inference or byte reads.

Evidence version 2 adds an ordered `collectionOmissions` list with at most two entries: local `global_window_limit`, followed by at most one of `model_window_limit`, `model_requested_byte_limit` or `reference_work_limit`. More than 32 distinct origins retains the first deterministic 32 and records the local omission. The first aggregate/work cutoff stops collection and attaches its uncertainty to every retained global. A later normally emitted global receives constant-size empty evidence carrying that actual cutoff. A missing eligible origin without a real cutoff still fails integrity checks. Omissions give no omitted count, address span or initializer semantics. They remain separate from `unknown_access_width` and per-segment unavailable bytes.

Serialized models still reject over-budget or malformed payloads; omission markers do not waive limits. Empty supplied windows require an aggregate/work cutoff. Module prompts allow 65,536 decoded available bytes and 524,288 rendered evidence bytes, including omission metadata, and fail before agent invocation if exceeded. Prompts distinguish unsupplied evidence from collection omissions. Existing artifact, token, depth, cancellation and execution limits also apply; cancellation and integrity failures never become omission reasons.

Schemas 1 and 2 retain their historical canonical representation without a wire byte-evidence field. Schema 3 requires its original nonnull version-1 evidence and preserves historical canonical bytes. Schema 4 requires the key with null or version-2 evidence; mixed versions and absent keys refuse. Production capture/planning/resume requires schema 4 with exporter 17 (exporter 13 emitted the same schema-4 model; 17 adds the parallel, diagnostic and retry changes described in `oracle/gcc/16.2.0/README.md`), nonnull eligible-global evidence and the matching staged exporter digest. Old model/profile/content commitments cannot be promoted by changing a header; historical checkpoints and qualified input receipts remain unchanged.

Active GCC controls are `oracle/gcc/16.2.0/compiler-engines-exporter17.json` (the serial default) and `structural-full-export-profile-exporter17.json`, plus the explicit parallel runtime-6 profile `compiler-engines-exporter17-parallel.json`. Their exporter SHA is bound to the staged Java source. Unsuffixed exporter-11 and suffixed exporter-12 and exporter-13 profiles remain historical evidence; loading them as current production controls fails the implementation identity check.

The authored bundled ProgramDB control disassembles MOVSD, ADDSD and MULSD to actual COPY, FLOAT_ADD and FLOAT_MULT p-code. It deliberately defines a one-byte `00h` listing at each referenced constant and checks that export preserves that initializer while retaining all eight leading-zero memory bytes. This controlled listing setup does not establish how an unmodified input is naturally analyzed; natural listing observations and corrected input qualification require separate evidence.

Qualification also includes the bundled public Java API memory probe and an opt-in stripped ELF fixture containing explicit eight-byte loads of raw binary64 0.5, 0.25 and 8.0. The fixture independently checks ELF symbol addresses and PT_LOAD file bytes, then verifies the recovered bytes after stripping. The `bundled-ghidra` Actions job enables the real fixture. Exported bytes establish input availability only; a separate newly frozen experiment is required for any later ACP measurement.
