# Authenticated generic template evidence: design proposal

**Review artifact for the open design issue.** This document proposes a bounded contract and implementation issue set for independent review. It is not a frozen or accepted contract, and authorizes no producer, observation sink, truth projection, schema migration, or production qualification. The reviewed repository baseline is master commit `e5ff2c537c09eb3c048cba80a1ac53dcf00f2d6a` (merged PR #1469).

## Decision

Use a versioned Clang frontend evidence adapter as the first supported generic-template provider. It must run with the exact Clang frontend authenticated for the build action, over the authenticated source and build inputs, and record compiler-owned declaration relationships and typed template arguments. A separate raw-input validator replays that action and regenerates the evidence. The serialized frontend output is a transport artifact, never truth by virtue of its own digest.

DWARF remains the source of physical emitted-instance evidence. Frontend pattern facts and DWARF DIE facts have different physical locators and are not joined by names, mangling, candidate hashes, offsets, visitation order, or approximate coordinates. DWARF5 §2.23 explicitly says the format does not represent generic definitions, but represents each instantiation and its actual parameters; §3.3.7 and §5.7.7 make the same limitation for function and class templates. Therefore a missing frontend proof remains unknown. The GCC and Clang DWARF5 records inspected for #1469 show typed concrete instances but no generic-pattern-to-instance edge. The accepted ordinary `DW_AT_abstract_origin` edge in #1469 is inline evidence only.

The generic facts use a new `full-tree-generic-template-evidence-v1` schema/policy. They do not extend observation-v2 or truth-v3. When they are eventually projected, use additive observation-v3 and truth-v4 paths; keep observation-v1/v2 and truth-v2/v3 schemas, policies, digests, APIs, and migration vectors byte-for-byte unchanged. The generic source census remains separate from emitted-RVA score denominators.

## Evidence and feasibility

| Evidence inspected | What it supports | Limit |
| --- | --- | --- |
| Official DWARF5 §2.23, §3.3.7, §5.7.7 | Concrete template-instance DIEs and typed actual parameters can be retained. | No portable generic-definition DIE or mandatory pattern-to-instance link. |
| Merged #1469 at the reviewed baseline; source-identity producer/model and fixture report | Bounded artifact-bound DIE rows, ordered typed actuals, concrete candidate identities, unknown generic links, digest-bound scope/inventory, and existing no-partial-publication controls. | It intentionally has no source/frontend generic relation. |
| Clang LibTooling and AST API documentation | A `ClangTool` runs a `FrontendAction` with a compilation database; `FunctionDecl::getPrimaryTemplate`, `ClassTemplateSpecializationDecl::getSpecializedTemplateOrPartial`, and `getTemplateArgs` expose semantic links and typed actuals. | This is a Clang-specific interface. Its records still require authenticated inputs and raw replay. |
| Clang JSON compilation database specification | A command entry records the working directory, main source and compile command; the `arguments` vector is preferred over shell text. | A database describes a command; it does not attest that it ran or that its ambient files/environment were controlled. |
| Official GCC template-instantiation documentation | GCC may emit duplicate instances per translation unit and let the linker discard duplicates. | Emission/linker behavior is not a generic source identity relation. GCC is not a v1 frontend provider. |

The feasibility claim is deliberately narrow: Clang's semantic AST APIs offer direct template declaration pointers and ordered `TemplateArgument` values, so a bounded C++ `FrontendAction` can serialize those relationships without parsing names. PR #1469 already established that the selected C++ compiler fixtures contain the concrete-instance side of the evidence and that the DWARF side lacks the generic edge. The first implementation should exercise a pinned Clang 18.1.3 fixture profile (also used by #1469's recorded fixture matrix) and record the exact executable/runtime digests; version text alone is not authentication. No claim is made that GCC's frontend has equivalent stable API coverage, that any production build has been requalified, or that Clang and GCC ASTs are interchangeable.

Pinned Clang 18.1.3 primary API sources: [`DeclTemplate.h`](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/AST/DeclTemplate.h#L1774-L1812) documents the selected class partial and its deduced `getTemplateInstantiationArgs()`; lines [436–612](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/AST/DeclTemplate.h#L436-L612) distinguish `FunctionTemplateSpecializationInfo::TemplateArguments` from `TemplateArgumentsAsWritten` and document the separate `MemberSpecializationInfo` relationship/kind. [`Decl.h`](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/AST/Decl.h#L2583-L2663) defines `FunctionDecl` member/template-specialization APIs and [`FunctionDecl::getNameInfo()`](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/AST/Decl.h#L1969-L1972). [`DeclarationName.h`](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/AST/DeclarationName.h#L694-L801) defines `DeclarationNameInfo::getSourceRange()` and multi-token name locations; [`Lexer.h`](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/Lex/Lexer.h#L366-L394) defines token-end and character-range conversion. The traversal pins [`TemplateDecl::getTemplatedDecl()`](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/AST/DeclTemplate.h#L402-L404), the class partial ordered-list overload (lines [2163–2165](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/AST/DeclTemplate.h#L2163-L2165)), class specialization range (lines [2201–2213](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/AST/DeclTemplate.h#L2201-L2213)), and [function specialization ranges](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/AST/DeclTemplate.h#L983-L995). The exact type normalization API is pinned to [`QualType::getCanonicalType()` and `getSplitUnqualifiedType()` in `Type.h`](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/AST/Type.h#L944-L981), and macro descriptor fields to [`MacroInfo.h`](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/Lex/MacroInfo.h#L163-L196). The exact frontend call path is pinned to [`ToolInvocation` in `Tooling.cpp`](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/lib/Tooling/Tooling.cpp#L329-L435): it builds the driver invocation from the supplied vector, then runs the supplied action; the same source shows [`ClangTool` installs three default adjusters and injects a resource directory](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/lib/Tooling/Tooling.cpp#L437-L479). Therefore the v1 adapter uses `ToolInvocation` directly and does not use `ClangTool` or call `ClangTool::run`. These APIs are the v1 profile contract, not claims that another Clang release or frontend is wire-compatible. Primary references: [DWARF5](https://dwarfstd.org/doc/DWARF5.pdf), [Clang LibTooling](https://clang.llvm.org/docs/LibTooling.html), [Clang JSON Compilation Database](https://clang.llvm.org/docs/JSONCompilationDatabase.html), [Clang `FunctionDecl`](https://clang.llvm.org/doxygen/classclang_1_1FunctionDecl.html), [Clang `ClassTemplateSpecializationDecl`](https://clang.llvm.org/doxygen/classclang_1_1ClassTemplateSpecializationDecl.html), and [GCC template instantiation](https://gcc.gnu.org/onlinedocs/gcc/Template-Instantiation.html).

## Trust inputs and authentication contract

The producer and validator would accept only the following proposed input chain. Every digest below is SHA-256 over the exact canonical bytes or file bytes named; no caller-provided digest is accepted without rereading and validating its input.

1. **Source identity.** Reuse the authenticated scope, source lock, artifact manifest, source archive, source inventory, generated-file inventory/provenance, and the source-root path normalizer. Bind the Git source revision/tree identity, archive bytes, every translation-unit source blob, every generated source/header, and every opened include. Reject dirty, replaced, symlink-escaping, missing, or digest-mismatched inputs. A file outside the authenticated source/generated/toolchain closure makes that translation unit unsupported; it is not silently read from the host.
2. **Build action.** Reuse the authenticated build-record and compiler-action/compilation-database inputs. Select one unique action by authenticated `unitId` and exact argv digest. Require the authenticated compilation database to express cwd and every path-bearing argument in closure-relative virtual paths before authentication; resolve those virtual paths to contained files. Canonicalize the argv as an ordered string array, cwd, main file, target triple, language mode, ordered `-D`/`-U` definitions, include search order, forced includes, response-file bytes, sysroot, resource directory, and PCH/module inputs. Require the compilation-database `arguments` string array; reject shell `command` entries in v1. The original top-level `arguments` vector must already contain exactly one standalone `--no-default-config` token; reject the action if it is absent or occurs more than once, and do not count a token that appears only after response-file expansion. Never insert, remove, reorder, or otherwise rewrite it or any other semantic argument. This v1 requirement excludes ambient Clang default config files without adding them to the authenticated input set. Require argv[0] to be `/__decomp/toolchain/<profile-relative>/bin/clang`, mapped to its authenticated bytes; path operands use relative paths under the authenticated virtual cwd or absolute paths under `/__decomp/{source,generated,build,toolchain}`. Reject host absolute paths in argv/cwd. Preserve every argument byte-for-byte as UTF-8 strings and in order after that compilation database is authenticated. The adapter calls Clang 18.1.3 `clang::tooling::ToolInvocation` directly with that vector, the authenticated cwd/VFS, and the evidence `FrontendAction`; it does not call `ClangTool`, apply argument adjusters, insert a resource-directory flag, or launch a second compiler. The Clang driver translates that original vector to frontend options; the custom action parses the AST and never creates code-generation output. Reject preprocessor/dependency-only actions (`-E`, `-M`, `-MM`), save-temps/output-producing dependency flags (`-save-temps*`, `-MD`, `-MMD`, `-MF`, `-MT`, `-MQ`, `-MJ`, `-dependency-file`) and unauthenticated response files. Exact `-c` and `-o` entries may remain because this action does not open an object output; acceptance fixtures must verify absence of output side effects. Bind the exact environment allowlist below; clear every other variable. Do not treat the repo's current Clang capture-input or Ninja prestart object as execution evidence: those objects are explicitly unexecuted.
   Clang 18.1.3 declares this driver flag as disabling default configuration-file loading in its pinned [`Options.td`](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/Driver/Options.td#L1023-L1029); the exact-token policy above also authenticates the action that selected it.
3. **Frontend identity.** Bind a registered `clang-libtooling-cxx-v1` profile to compiler executable SHA-256, Clang/LLVM runtime and loaded-library closure digests, resource-header manifest digest, adapter source revision, adapter executable digest, adapter ABI/API version, target triple, and the existing toolchain reproduction/profile digest. Resolve the compiler by its authenticated absolute virtual path; `PATH` cannot select or replace it. `--version` output is diagnostic only. Reject an unregistered profile, a substituted executable/library, an implicit host `PATH` lookup, or a compiler different from the compiler authenticated for the build action. For v1, GCC, MSVC, clang-cl, and a Clang frontend substituted for a GCC-built artifact have capability `unsupported`, not a guessed fallback.
4. **Preprocessor/build context.** The frontend argument transform is the identity function: `frontendArgv[i] = compilationDatabase.arguments[i]` for every ordinal, including argv[0]. No `ClangTool` adjuster or implicit resource-dir argument is allowed. The execution receipt records the exact input vector, cwd, environment, driver-resolved resource directory, actual ordered include/dependency closure with per-file hashes, generated inputs, and a deterministic preprocessor-context digest over active macros, include resolution, language/target options, and authenticated PCH/module inputs. The full argv/environment/action digest binds every option, including optimization and debug flags. V1 rejects PCH/modules; accepting them requires a later policy/schema version that authenticates their full artifacts and import closure. The full action and runner context are provenance, not part of the semantic anchor preimage; the anchor includes source revision/blob and complete typed declaration/argument facts. Therefore `-O0` and `-O2` may yield the same candidate when that tuple matches, while their action and physical IDs differ. A macro/configuration change changes the authenticated semantic-context digest and action/physical IDs; candidate equality still never merges or links rows.
5. **Executed frontend receipt.** The bounded isolated runner records deterministic action success, authenticated compiler/profile/action digests, dependency digests observed by the frontend, preprocessor-context digest, zero compiler-artifact output bytes, exit status, and action ID in the canonical receipt. CPU, wall, memory, stdout, and stderr telemetry stays in a non-evidence runner log. Once canonical evidence output is complete, an enclosing authenticated output inventory binds its SHA-256 and byte count. A planned command, compile database row, stderr/stdout text, compiler version string, or producer-authored JSON is not an execution receipt. On any failed command, changed input, missing include, resource termination, or receipt mismatch, publish no partial facts.

The current Kotlin trust chain is a viable base: `FullTreeScopeControl` snapshots and validates the exact scope/source-lock/manifest/build-record bindings; `FullTreeSourceInventoryControl` checks the locked source archive and per-file inventory; `FullTreeFunctionObservationProducer.authenticateShardInputs` binds inventory and rich-artifact bytes; and the #1469 producer enforces authenticated per-shard and no-partial-output budgets. The gap is explicit: current `FullTreeClangCaptureInputControl` and Ninja prestart represent validated but unexecuted inputs. The first implementation issue must add a frontend execution receipt instead of upgrading either plan object by implication.

## Schema and identities

### Proposed wire and digest contracts

The proposal defines four independently registered contracts that would freeze wire, policy, and compatibility versions. All objects use `additionalProperties: false`; every listed member is required, and nullable members are present as JSON `null`. Empty arrays/objects, null, zero, and omitted members are distinct. Hashes are lowercase 64-character SHA-256 hex. JSON integers are non-negative and at most signed 64-bit; arbitrary-width C++ integral values are canonical base-10 strings. Strings use strict UTF-8 with no Unicode normalization. Arrays preserve declared order unless this section specifies canonical sorting. `schemaVersion` is independent of the `vN` registry name; truth-v4's schema name is `...v4` while its new wire `schemaVersion` is 3, advancing the #1468 wire version 2.

| Contract | Registry/schema name | Wire version | Policy id/version | Configuration digest input |
| --- | --- | ---: | --- | --- |
| Frontend receipt/provenance | `full-tree-generic-template-frontend-v1` | `schemaVersion: 1` | `full-tree-generic-template-frontend` / 1 | `OracleSchemas.configurationSha256([name], canonicalPolicy)`; canonical policy JSON followed by exact bundled schema bytes. |
| Generic evidence | `full-tree-generic-template-evidence-v1` | `schemaVersion: 1` | `full-tree-generic-template-evidence` / 1 | Same rule, evidence schema and evidence policy only. |
| Function observation | `full-tree-function-observations-v3` | `schemaVersion: 3` | `full-tree-function-observations` / 5 | Same rule, new v3 schema/policy only; v1/v2 schema and policy bytes stay frozen. |
| Function truth shard/index | `full-tree-function-truth-v4`, `full-tree-function-truth-index-v4` | `schemaVersion: 3` in each | `full-tree-function-truth` / 4 | `OracleSchemas.configurationSha256(["full-tree-function-exclusions", "full-tree-function-truth-v4", "full-tree-function-truth-index-v4"], canonicalPolicy)`, in exactly that order. |

For frontend/evidence policies, the canonical policy JSON has exactly `id`, `version`, `argvPolicy`, `environmentAllowlist`, `supportedEntityKinds`, `supportedDeclarationKinds`, `supportedEdgeKinds`, `supportedStatusKinds`, `supportedSpecializationKinds`, `supportedQualifierKinds`, `supportedTypeKinds`, `supportedArgumentKinds`, `unsupportedKinds`, `reasonCodes`, and `limits`. `argvPolicy` is the exact closed string `clang-toolinvocation-exact-arguments-v1`: pass the authenticated compilation-database argument vector unchanged to `ToolInvocation`; no argument adjuster or resource-dir insertion is permitted. Each array is sorted unique and exactly the closed enums/allowlist written below; `reasonCodes` is exactly the closed evidence reason enum below. `limits` contains only fixed policy ceilings: `maxFormalsOrActualsPerEntity: 1024`, `maxEdgesPerEntity: 32`, `maxRelationWalkDepth: 32`, `maxTypeDepth: 64`, `maxTypeNodesPerDescriptor: 4096`, `maxEntityRowBytes: 67108864`, `maxGenericEvidenceBytes: 67108864`, `maxResourceHeaderFiles: 65536`, `maxResourceHeaderManifestBytes: 67108864`, `maxResourceHeaderTreeBytes: 1073741824`, `genericResidentShareDivisor: 4`, `genericResidentCanonicalByteMultiplier: 3`, and `genericResidentFixedBytes: 64`. Authenticated whole-run action count, per-shard entity/output/resident limits, worker count, and runner limits come only from validated controls and are not copied into this policy object. The v1 policy arrays are exact: `supportedEntityKinds = ["concrete-instantiation","explicit-specialization","partial-specialization","primary-template","supporting-declaration"]`; `supportedDeclarationKinds = ["class","class-template","enum","function","function-template","other-named","record"]`; `supportedEdgeKinds = ["explicit-specializes","instantiates-function-template","instantiates-partial","instantiates-primary","member-specialization","redeclares","specializes-primary","templated-declaration"]`; `supportedStatusKinds = ["ambiguous","supported","unknown","unsupported"]`; `supportedSpecializationKinds = ["explicit-instantiation-declaration","explicit-instantiation-definition","explicit-specialization","implicit-instantiation","undeclared"]`; `supportedQualifierKinds = ["const","restrict","volatile"]`; `supportedTypeKinds = ["array","builtin","enum","function","lvalueReference","pointer","record","rvalueReference","templateParameter","templateSpecialization"]`; `supportedArgumentKinds = ["integral","pack","template","type"]`; and `unsupportedKinds = ["class-valued-nttp","concepts-requires","dependent-non-type-expression","dynamic-exception-specification-dependent","floating-nttp","module","other-calling-convention","other-clang-argument","other-clang-type","pch","pointer-nttp","unexpanded-pack","unresolved-dependent-actual","unresolved-template-name","variable-template"]`. These arrays use the stated order, which is their canonical lexical sort. The environment allowlist is the sorted unique set listed below. The policy's `reasonCodes` array uses the exact closed reason enum listed with the evidence row fields.

The observation-v3 policy JSON is the accepted #1467 v2 policy JSON with no existing member changed or removed, plus exactly `genericTemplates: "separate-nonscoreable-evidence-v1"`; its `id` is `full-tree-function-observations` and `version` is 5 (up from 4). The truth-v4 policy JSON is the accepted #1468 truth-v3 policy JSON with no existing member changed or removed, plus exactly `genericTemplates: "raw-rederived-nonscoreable-census-v1"`; its `id` is `full-tree-function-truth` and `version` is 4 (up from 3). No policy object contains source/build/artifact hashes, machine paths, run IDs, or compiler versions; those are envelope bindings. The configuration digest is computed once exact schema bytes exist; no placeholder/fabricated digest is accepted.

#### Frontend provenance envelope

The frontend provenance document has exactly `schemaVersion`, `policyId`, `policyVersion`, `configurationSha256`, `bindings`, `units`, and `counts`. `bindings` has exactly `scopeSha256`, `sourceLockSha256`, `artifactManifestSha256`, `buildRecordSha256`, `sourceArchiveSha256`, `sourceInventorySha256`, `generatedInventorySha256`, `richArtifactSha256`, `richInventorySha256`, `compilationDatabaseSha256`, and `frontendProfileSha256`. Units sort by `(unitId, actionId)`. The exact unit fields, resource-directory binding, deterministic receipt preimages, dependency ordering, and zero output-byte rule are specified in amendment 2; that specification supersedes this paragraph's earlier receipt shorthand. `sourcePath` is a closure-relative `source/<repo-relative>` or `generated/<inventory-relative>` path. `cwd` is the exact authenticated closure-relative virtual path `source/<repo-relative>`, `generated/<inventory-relative>`, or `build/<authenticated-relative>`; `ToolInvocation` runs with the corresponding `/__decomp/<cwd>` working directory, and no host absolute cwd is serialized. `argv` is the exact already-normalized compile-database `arguments` array, unchanged. `dependencies` contains `{path, sha256, role}` records; response-file bytes are authenticated before Clang expands them, and v1 rejects PCH/modules. `environment` contains sorted allowlisted string values only. `counts` has exactly `unitCount`, `dependencyCount`, and `outputBytes`.

The v1 environment allowlist is exactly the sorted array `CPATH`, `CPLUS_INCLUDE_PATH`, `C_INCLUDE_PATH`, `HOME`, `LANG`, `LC_ALL`, `OBJCPLUS_INCLUDE_PATH`, `OBJC_INCLUDE_PATH`, `PATH`, `SDKROOT`, `SOURCE_DATE_EPOCH`, and `TMPDIR`. Absent variables are omitted, not null. `PATH` entries are absolute virtual paths under `/__decomp/toolchain/`. `HOME` and `TMPDIR` are fixed virtual paths `/__decomp/home` and `/__decomp/tmp`, mounted as empty contained per-action directories; both their virtual names and empty contents are bound. `PATH` uses authenticated virtual toolchain paths, and `SDKROOT` uses a profile-relative virtual path. No host path appears in the environment object. Include-path and SDK variables are accepted only when their resolved files are in the authenticated dependency closure. Any non-allowlisted variable or unreadable environment input rejects the action.

#### Generic-evidence envelope and rows

The evidence document has exactly `schemaVersion`, `provider`, `policyId`, `policyVersion`, `configurationSha256`, `bindings`, `units`, `entities`, `edges`, and `counts`. `provider` is exactly `clang-libtooling-cxx-v1`. `bindings` has exactly the eleven provenance digest members above plus `frontendReceiptSha256` and `dwarfArtifactSha256`; the evidence artifact digest and byte count live only in the enclosing authenticated output inventory. Each evidence unit has exactly `unitId`, `actionId`, `sourcePath`, `sourceFileSha256`, `argvSha256`, `cwd`, `environmentSha256`, `semanticContextSha256`, `frontendProfileSha256`, `dependencySetSha256`, and `receiptSha256`, matched to the authenticated receipt. Entity rows sort by `(unitId, ordinal)` and require exactly `physicalId`, `unitId`, `ordinal`, `entityKind`, `declarationKind`, `nameRaw`, `spellingLocation`, `expansionLocation`, `lexicalParentPhysicalId`, `semanticParentPhysicalId`, `status`, `reasonCodes`, `formals`, `signature`, `specializationKind`, `semanticAnchorCandidateId`, `resolvedSemanticIdentityId`, and `identityProofKind`. Nullable-but-required fields are `nameRaw`, both locations, both parent IDs, `signature`, `specializationKind`, both IDs, and `identityProofKind`. In evidence-v1, `resolvedSemanticIdentityId` and `identityProofKind` are always required JSON nulls. `entityKind` is `primary-template`, `partial-specialization`, `explicit-specialization`, `concrete-instantiation`, or `supporting-declaration`; `declarationKind` is `class`, `function`, `class-template`, `function-template`, `record`, `enum`, or `other-named`. `status` is `supported`, `unsupported`, `unknown`, or `ambiguous`; `reasonCodes` is sorted and unique from this closed enum: `ambiguous-template-selection`, `argument-vector-incomplete`, `conflicting-redeclaration-default`, `cross-unit-target`, `invalid-source-location`, `limit-exceeded`, `missing-source-anchor`, `missing-template-relation`, `semantic-anchor-conflict`, `unauthenticated-input`, `unresolved-dependent-actual`, `unsupported-argument-kind`, `unsupported-compiler-profile`, `unsupported-concept`, `unsupported-language-mode`, `unsupported-module`, `unsupported-pch`, `unsupported-template-kind`, and `unsupported-type-kind`.

A location is exactly `{path, byteOffset, line, column, macroExpansionDepth}`. `line`/`column` use physical source coordinates from the spelling file and byte offset (`SourceManager` file line/column getters); presumed `#line` coordinates never replace them. `nameRaw` is the exact UTF-8 byte slice of the authenticated original source span: for a simple identifier, start at the direct declaration name token location and end at `Lexer::getLocForEndOfToken`; for overloaded operators, conversion/literal operators, constructors/destructors, and any other multi-token declaration name, use the direct `DeclarationNameInfo::getSourceRange()` (including the operator keyword and full conversion type as applicable), then take the byte interval from its first token through `Lexer::getLocForEndOfToken` at its last token. For a `TemplateDecl` wrapper, obtain the name span only from its direct `getTemplatedDecl()` pointer and verify that declaration's source location; do not perform a name lookup. Convert spelling endpoints to one authenticated file and original-file byte offsets. The half-open span includes all original whitespace/comments between its first and last name tokens, excludes surrounding trivia, and is never reconstructed from a pretty-printer, demangler, `DeclarationName::getAsString()`, or normalized identifier. Decode the slice as strict UTF-8 without normalization. If the range is invalid, non-contiguous, macro scratch/unmapped, crosses files, contains invalid UTF-8, or cannot be read from an authenticated source file, encode `nameRaw:null`, add `missing-source-anchor`, and withhold the candidate. Tests pin identifiers, `operator+`, `operator new`, conversion operators with multi-token types, literal operators, and macro-generated names. The pinned APIs are Clang 18.1.3 `DeclarationNameInfo::getSourceRange()` and `Lexer::getLocForEndOfToken`; the lexer returns an invalid end when it cannot form a file location.

Map Clang declarations to the closed `declarationKind` enum with this ordered rule set: `ClassTemplateDecl` → `class-template`; `FunctionTemplateDecl` → `function-template`; `CXXRecordDecl` (class, struct, union, including specializations/partials) → `class`; `FunctionDecl` → `function`; `RecordDecl` not already matched as `CXXRecordDecl` → `record`; `EnumDecl` → `enum`; any other `NamedDecl` → `other-named`. The order is significant because template wrappers and `CXXRecordDecl` inherit from broader named/record classes. Non-`NamedDecl` nodes are not entity rows. `TranslationUnitDecl` is the only non-named parent represented by null; if another non-named `DeclContext` occurs in a required parent chain or a required relation target is not a `NamedDecl`, v1 rejects the action rather than dropping a direct parent or fabricating `other-named`. This mapping uses the direct Clang dynamic type only; no spelling heuristic participates.

Each entity parent ID is a direct pointer reference from `getLexicalDeclContext()` or `getDeclContext()` respectively; both parent chains are retained separately, point to same-unit supporting/template rows, and are null only at the translation-unit root. Each formal has exactly `depth`, `index`, `kind`, `isPack`, `declaredType`, `defaultArgument`, and `nestedFormals`. `kind` is `type`, `nonType`, or `templateTemplate`. `declaredType` is null for type/template-template formals and a `TypeDescriptor` for non-type formals. `defaultArgument` is null or a tagged `TemplateArgument`; defaults are merged across canonical redeclarations before candidate hashing as specified in amendment 1. `nestedFormals` is empty for type/non-type formals and holds the ordered nested formal list for template-template formals. Signature is null when not applicable, otherwise exactly `{result, parameters, variadic, memberCvQualifiers, memberRefQualifier, callingConvention, exceptionSpecification}`; `exceptionSpecification` uses the same required `{kind,types}` object defined for function types. Qualifier arrays use only `const`, `volatile`, and `restrict`, sorted and unique; member ref qualifier is null, `lvalue`, or `rvalue`. `variadic` is a JSON boolean. Calling convention is one of `cdecl`, `stdcall`, `fastcall`, `thiscall`, `vectorcall`, `aapcs`, `win64`, `sysv64`, `preserve-most`, or `preserve-all`; any other target calling convention makes that signature unsupported. Parameter arrays preserve ordinal order.

`TypeDescriptor` is a closed tagged object. Supported variants and exact fields are: `builtin` (`kind,name,qualifiers`, where `name` is the Clang 18.1.3 `BuiltinType::Kind` enumerator, never `QualType::getAsString()`); `record` or `enum` (`kind,qualifiers,declPhysicalId`); `pointer` (`kind,qualifiers,pointee`); `lvalueReference` or `rvalueReference` (`kind,qualifiers,referent`); `array` (`kind,qualifiers,element,bound`, where bound is null or canonical decimal); `function` (`kind,qualifiers,result,parameters,variadic,memberCvQualifiers,memberRefQualifier,callingConvention,exceptionSpecification`); `templateParameter` (`kind,qualifiers,depth,index`); and `templateSpecialization` (`kind,qualifiers,specializationPhysicalId,templatePhysicalId,arguments`). Every descriptor variant has a required `qualifiers` array; its supported values are exactly `const`, `volatile`, and `restrict`, sorted and unique. Any other qualifier bit, including `atomic`, address-space, Objective-C, GC, or unaligned qualifiers, is unsupported. `memberCvQualifiers` uses only `const` and `volatile`. `exceptionSpecification` is exactly `{kind,types}`, where kind is `none`, `noexcept-true`, `noexcept-false`, or `dynamic`; `types` is empty except for supported C++14 dynamic exception specifications and then contains the ordered typed exception list. Dependent/unresolved exception specifications are unsupported. Every variant has exactly the listed fields. For `templateSpecialization`, `specializationPhysicalId` points to the exact same-unit `ClassTemplateSpecializationDecl` fact and `templatePhysicalId` to its primary `ClassTemplateDecl`; ordered actuals are the specialization's direct `getTemplateArgs()` vector. The selected primary/partial disposition is read from that specialization entity's typed edge, not inferred from the type spelling. All declaration references resolve to same-unit `supporting-declaration` or template entities via direct Clang AST pointers. Supported `TemplateArgument` variants are exactly: `type` (`kind,type`); `integral` (`kind,type,isSigned,bitWidth,value`); `template` (`kind,templatePhysicalId`); and `pack` (`kind,elements`), recursively preserving ordinals. Each has exactly the listed fields. Other Clang argument/type forms use `{kind:"unsupported",clangKind,rawSha256}` and force row status `unsupported` with null candidate and resolved ID. `rawSha256` is nullable and uses only the exact authenticated token-range algorithm specified in amendment 3. No pretty-printed type is a semantic substitute.

#### Edge union and Clang specialization mappings

`edges` sort by `(unitId, sourcePhysicalId, kind, targetPhysicalId, canonicalRelationPayloadBytes)`, where the payload is `OracleJson.canonicalBytes({proofKind,specializationKind,argumentVectors})` compared unsigned bytewise. Each edge has exactly `unitId`, `sourcePhysicalId`, `targetPhysicalId`, `kind`, `proofKind`, `specializationKind`, and `argumentVectors`; `specializationKind` is nullable. Endpoints resolve to same-unit entities. Closed `kind` values are `templated-declaration`, `redeclares`, `specializes-primary`, `instantiates-primary`, `instantiates-partial`, `instantiates-function-template`, `member-specialization`, and `explicit-specializes`. `proofKind` is one exact API trace: `ClassTemplateSpecializationDecl.getSpecializedTemplateOrPartial`, `ClassTemplateSpecializationDecl.getSpecializedTemplate`, `FunctionDecl.getPrimaryTemplate`, `FunctionDecl.getPreviousDecl`, `RecordDecl.getPreviousDecl`, `ClassTemplateSpecializationDecl.getPreviousDecl`, `ClassTemplatePartialSpecializationDecl.getPreviousDecl`, `ClassTemplateDecl.getPreviousDecl`, `FunctionTemplateDecl.getPreviousDecl`, `FunctionDecl.getMemberSpecializationInfo->MemberSpecializationInfo.getInstantiatedFrom`, `ClassTemplateDecl.getTemplatedDecl`, or `FunctionTemplateDecl.getTemplatedDecl`. The direct edge receiver and returned declaration pointer are checked under the Clang 18.1.3 profile. Class/function argument-vector fields are independently read from the exact getters specified below: `getTemplateArgs()` / `getTemplateInstantiationArgs()` for class templates, and `getTemplateSpecializationArgs()` / `getTemplateSpecializationArgsAsWritten()` for functions (equivalent to `FunctionTemplateSpecializationInfo::TemplateArguments` / `TemplateArgumentsAsWritten`). `Decl.getCanonicalDecl()` is reserved for same-ASTContext identity grouping, never used to invent an edge. `argumentVectors` always has exactly five required nullable keys: `primaryActuals`, `partialDeducedArguments`, `partialPatternArguments`, `functionActuals`, and `functionArgumentsAsWritten`. For no-binding edges (`templated-declaration`, `redeclares`, `member-specialization`) all five are null. Other vectors are populated only as follows.

Vector ordinals are normative: `primaryActuals` and `partialPatternArguments` align with the primary template formals in depth/index order; `partialDeducedArguments` aligns with the selected partial specialization’s own formal depth/index order; `functionActuals` aligns with the selected primary function template’s formals. A pack remains one formal slot whose `pack.elements` preserve inner ordinals. `functionArgumentsAsWritten` preserves only explicit source-written arguments in their written order, may be shorter than the instantiated vector, and is not padded or reindexed. Defaulted/deduced values remain in the corresponding compiler-instantiated vector.

The vector matrix is exhaustive: `templated-declaration` and `redeclares` require all vectors null and null specialization kind; `specializes-primary` requires only `partialPatternArguments`; `instantiates-primary` requires only `primaryActuals`; `instantiates-partial` requires `primaryActuals` plus `partialDeducedArguments`; `instantiates-function-template` requires `functionActuals` and nullable `functionArgumentsAsWritten`; `member-specialization` requires all vectors null and a non-null member specialization kind; `explicit-specializes` requires `primaryActuals` for class specializations or `functionActuals` plus nullable written arguments for function specializations. Every other vector is null. The specialization kind is exactly one of `undeclared`, `implicit-instantiation`, `explicit-specialization`, `explicit-instantiation-declaration`, or `explicit-instantiation-definition`, copied from the matching Clang `TemplateSpecializationKind`; it is null for `templated-declaration`, `redeclares`, and `specializes-primary`.

For each entity, the authoritative edge source for its five `argumentVectors` is determined only by entity class: `primary-template` and `supporting-declaration` have no authoritative binding edge and use no candidate binding vectors; `partial-specialization` uses exactly its direct `specializes-primary` edge's `partialPatternArguments`; a concrete class primary uses exactly its direct `instantiates-primary` edge's `primaryActuals`; a concrete class selected through a partial uses exactly its direct `instantiates-partial` edge's `primaryActuals` and `partialDeducedArguments`; a concrete function template specialization uses exactly its direct `instantiates-function-template` edge's `functionActuals` and optional `functionArgumentsAsWritten`; class explicit specializations use exactly their direct `explicit-specializes` edge's `primaryActuals`; function explicit specializations use exactly their direct `explicit-specializes` edge's `functionActuals` and optional written vector. V1 accepts an `explicit-specializes` class edge only when Clang's direct target is the primary `ClassTemplateDecl`; a partial target or otherwise unrepresentable selection remains unknown/unsupported until a separately versioned vector shape is reviewed. `redeclares`, `templated-declaration`, and `member-specialization` never supply candidate argument vectors; a member-specialization edge remains independent metadata. If a row has zero required authoritative edges, an ineligible edge kind, an edge to the wrong declaration class, or more than one non-identical eligible edge, mark it `unknown` with `ambiguous-template-selection` or `argument-vector-incomplete` and withhold its candidate; never select the first edge. Exact duplicate relation observations normalize to one edge. Within a canonical redeclaration group, normalize the direct binding relation payloads against canonical target anchors: repeated identical payloads count once, while missing or conflicting payloads withhold the group's candidate. Retain every distinct typed edge as evidence.

For `ClassTemplateSpecializationDecl`, `getTemplateArgs()` is `primaryActuals`; the edge target is the exact pointer returned by `getSpecializedTemplateOrPartial()`. If the target is a primary template, `partialDeducedArguments` is null. If the target is a selected partial, `getTemplateInstantiationArgs()` is the separate `partialDeducedArguments` vector, deduced for the partial's own formals. The partial declaration's own `specializes-primary` edge carries `partialPatternArguments` from `ClassTemplatePartialSpecializationDecl::getTemplateArgs()` in the normalized typed pattern order; `getTemplateArgsAsWritten()` source span/raw bytes remain independently authenticated evidence. Example: `template<class T> struct Box; template<class T> struct Box<T*> {}; Box<int*> value;` yields `primaryActuals = [type(pointer(int))]`, selected target `Box<T*>`, and `partialDeducedArguments = [type(int)]`. Encoding both as `[type(int*)]`, swapping them, or deriving either from rendered names fails rederivation. For a primary-only class instantiation Clang specifies that `getTemplateInstantiationArgs()` equals `getTemplateArgs()`; v1 records it only as `primaryActuals` and keeps the partial vector null.

For function templates, `FunctionTemplateSpecializationInfo::TemplateArguments` supplies `functionActuals`; `TemplateArgumentsAsWritten` supplies `functionArgumentsAsWritten` when present, otherwise it is null. Function templates are not partially specialized in C++; overload selection is the exact `FunctionTemplateDecl*` returned by Clang. For member-function specializations, serialize the function-template edge and the independent `MemberSpecializationInfo` edge separately. The member edge has null argument vectors and its own `TemplateSpecializationKind`; never copy the function template's specialization kind onto it. Clang's documented `A<int>::f<int>` example is both a function-template specialization and a member specialization, and the two specialization kinds can differ. Class partial selection, its primary ancestor edge, function-template specialization, and member-specialization edge remain distinct. Edges with no binding, including `redeclares` and `templated-declaration`, encode the required all-null argumentVectors object; they never infer a binding from parameter spelling.

The evidence `counts` object has exactly `unitCount`, `entityCount`, `edgeCount`, `reasonCodeCount`, `entityKindCounts`, `edgeKindCounts`, `statusCounts`, and `reasonCounts`. Each `*Counts` object has exactly every enum key from its corresponding closed wire enum and a non-negative integer value, including explicit zeroes. Scalar totals equal array lengths; entity-kind and status maps sum to `entityCount`, edge-kind map sums to `edgeCount`, and reason map sums to total reason-code occurrences `reasonCodeCount`.

For v1, support only C++14 class/struct and function templates, primary declarations, class partial specializations, explicit specializations, explicit instantiations, observed implicit instantiations, overload sets, and packs. Formal kinds are type, integral/enum non-type, and template-template; supported actual kinds are type, integral/enum value, template name, and nested pack. A dependent type may appear in a partial-specialization pattern when encoded by supported `templateParameter` descriptors (for example `Box<T*>`); dependent/unresolved instantiated actuals, dependent non-type expressions, unexpanded pack expansions, and unresolved template names are tagged unsupported and cannot yield candidate/resolved identity. Unsupported variable templates, class-valued/floating/pointer NTTPs, concepts/requires, modules, unauthenticated PCH, and other Clang argument kinds are retained only as bounded tagged unsupported evidence. Expansion requires a new policy/schema version and fixtures.

## Bounds, failure behavior, and deterministic interface

The action interface consumes only validated typed registries and an authenticated immutable artifact root; it returns one immutable complete v1 result or a typed failure. It has no arbitrary path/output callback, no partial iterator that sinks can publish, and no ambient compiler selection. Production and raw-rederivation modes call the same strict input verifier but independently invoke the frontend over raw authenticated inputs. Candidate evidence is discarded before rederivation.

Use the smaller of caller limits and authenticated scope limits; do not raise any existing global, per-shard, DIE, function, parameter, serialization, or working-set bound. Propose these additional ceilings for policy v1:

| Item | Hard ceiling | Admission and failure |
| --- | ---: | --- |
| Actions | Authenticated `perShard.compilationUnits` and cumulative `wholeRun.compilationUnits`, plus existing worker ceiling | Count selected actions before launch; reject if any per-shard or cumulative run count exceeds its corresponding scope limit or if the worker ceiling is exceeded. |
| Entity/claim rows | Authenticated `perShard.entities` and cumulative `wholeRun.entities` | Count each physical #1467 source-entity row, each newly retained generic frontend entity, and each distinct ordinary emitted-definition anchor claim once in the run reconciliation model. Deduplicate repeated claims for the same #1467 physical DIE locator; never equate a frontend physical locator with a DIE locator. Do not recount a fact when repeated in evidence/observation/truth projections. Charge before retention; one over aborts the complete shard/run publication. |
| Formals or actual arguments per entity | 1,024 | Count nested pack leaves and nodes before retention; one over aborts. |
| Relationship edges per entity and relation walk | 32 each | Existing ceiling; one-over edge or chain aborts before publication. |

Count repeated evidence/observation-v3/truth-v4 entity rows, fixed envelopes, repeated bindings/unit rows, changed count maps, delimiters, and full-run index fields in every artifact where they appear.

If source locations, argument shapes, or types are syntactically readable but incomplete or conflicting, preserve bounded raw evidence and use `unknown`, `ambiguous`, or `unsupported`, with deterministic reason codes. If a declaration boundary, typed AST relation, or dependency closure cannot be established, abort that action. If a hard bound is exceeded, abort the shard before publishing any fact set. This is a review draft, not a frozen contract. ### 1. AST closure and redeclaration-group normalization

`DeclContext::decls()` is the lexical child source, but is not the whole declaration graph. For one `ASTContext`, walk from `TranslationUnitDecl` with this ordered, depth-first algorithm:

1. Visit each `DeclContext::decls()` child in the range's stored lexical order. Enter the child, finish its owned children, then advance to the next sibling.
2. On every `TemplateDecl`, visit the direct `getTemplatedDecl()` result first when non-null. Recurse into that declaration's `DeclContext` children before continuing.
3. For a `ClassTemplateDecl` canonical owner, materialize the ordered-list overload `getPartialSpecializations(SmallVectorImpl<ClassTemplatePartialSpecializationDecl*>&)` and visit that returned list, then visit `specializations()` from `spec_begin()` to `spec_end()` in the pinned Clang 18.1.3 API range order. For a `FunctionTemplateDecl` canonical owner, visit its `specializations()` range in API order. Load the owner range before traversal; v1 rejects PCH/modules and any item sourced from an external AST. These are compiler-owned edges, not entries assumed to occur in `DeclContext::decls()`.
4. For a redeclarable template owner, visit its declaration chain from canonical/oldest to most recent by materializing from `getMostRecentDecl()` through `getPreviousDecl()` and reversing that temporary vector. Enumerate each canonical owner's specialization collections once. A child reached by two owner paths is visited only at its first event.
5. On a non-template `DeclContext`, visit its `decls()` range in stored order. On a class specialization or function declaration reached through an owner collection, recurse into its declaration context where applicable.

Maintain `visitedDecls` and `activeDecls` as per-`ASTContext` pointer sets: an active revisit is a cycle and aborts the action; a completed revisit is deduplicated without another ordinal. Assign the next contiguous zero-based `eventOrdinal` to every unique `Decl*` on its first visit, including declarations outside the relevance set; only relevant declarations emit rows, so serialized row ordinals may have gaps. Pointer equality is never serialized. `getCanonicalDecl()` is used only in the separate grouping pass below, never to replace a physical visit. Direct relation targets and referenced named declarations enter the relevance set, but they are not appended from an unordered side table: if any required target is not reached by this ordered walk, abort the action with no evidence. The `ClassTemplateDecl::getPartialSpecializations()` returned order, class/function `specializations()` range order, redeclaration-chain order, and lexical `DeclContext` order are all explicit inputs to ordinals. Worker/action scheduling never participates.

After traversal, partition each unit's relevant redeclarable declarations by exact `Decl::getCanonicalDecl()` pointer equality within that `ASTContext`. Keep each distinct `Decl*` as a physical row and emit a `redeclares` edge for each direct `getPreviousDecl()` link. For each group, materialize declarations from canonical to most recent and normalize one shared semantic payload before calculating any candidate:

- Validate equal declaration kind, template parameter-list arity, nested template-template parameter shape, and each formal's `(depth,index,kind,isPack)` slot across all group members.
- For each formal slot, collect defaults from every redeclaration. Normalize a type default through the type algorithm below; normalize a non-type default only when Clang's constant evaluator returns a fully evaluated integral value; normalize a template-template default from its direct `TemplateArgumentLoc`. Packs use the same typed argument recursion. An inherited default contributes its value, not a second value. Deduplicate defaults by canonical typed JSON bytes. No default is `null`; exactly one distinct normalized value is that slot's merged default. Multiple distinct values, a dependent/unrepresentable default, a missing parameter slot, or incompatible signatures makes the entire group `unknown`, adds `conflicting-redeclaration-default` or `argument-vector-incomplete`, and withholds its candidate and resolved ID. Never pick the first, last, or canonical declaration's unmerged default.
- Use the canonical declaration's authenticated source anchor and raw token spelling; use the merged formals/defaults and normalized signature/specialization/semantic-argument vectors on every physical row in the group. Per-declaration spelling/expansion locations remain physical provenance.

For example, `template<class T, class U> struct Pair; template<class T, class U = int> struct Pair;` is one Clang canonical group. Both declaration rows carry the normalized formal vector `[T(default=null), U(default=type(builtin(int)))]` and therefore the same candidate. If separate TUs expose different default sets under macros, the normalized payloads produce different candidate values for the same source-anchor bucket; the full-run pass below marks that bucket ambiguous. Conflicting values never resolve through candidate equality.

Actual include/macro callbacks remain in callback order in `semanticContextSha256`.

`runtimeLibraryDigests` is exactly the sorted unique array of `{path,sha256}` rows for the complete dynamic-library closure actually loaded while the authenticated adapter runs the Clang 18.1.3 frontend. The v1 runner profile is Linux: the runner, outside the evidence producer, snapshots the isolated adapter PID's `/proc/<pid>/maps` after process startup and after action completion, unions file-backed executable/shared-object mappings, excludes the adapter executable itself, and hashes each remaining mapped file from the authenticated toolchain root. The pseudo mappings `[vdso]`/`[vsyscall]` are not files and are excluded; deleted, unreadable, unrecognized, or outside-root mappings reject the action. Paths are normalized under `toolchain/<profile-relative>/` only; all rows must resolve to regular files contained by the authenticated toolchain profile, with no symlink or host/system-library fallback. Rows sort by unsigned UTF-8 path bytes and paths are unique. Each row must match exactly one `dependencies` row with the same path/digest and role `toolchain-runtime`, and every `toolchain-runtime` dependency must appear in this array. The argv[0] Clang executable is authenticated separately as an exact `compiler-executable` dependency, whether or not `ToolInvocation` maps that file in the adapter process. An unenumerable loader dependency, outside-root library, mismatch, duplicate, or missing row rejects the frontend profile/action. The runtime array is part of `frontendProfileSha256`; the dependency array and digest bind the per-action observed closure.

For a unit, form `unitReceiptPreimage` by copying the exact unit object and removing exactly `argv`, `dependencies`, and `receiptSha256`; the removed arrays are already bound by `argvSha256` and `dependencySetSha256`. Then `receiptSha256 = H("decomp-thing/generic-template/unit-receipt/v1", unitReceiptPreimage)`. It includes the successful exit code and zero `outputBytes`, and has no runtime telemetry. The aggregate `frontendReceiptSha256` is not stored in its own preimage; compute it as `H("decomp-thing/generic-template/receipt-set/v1", {schemaVersion,policyId,policyVersion,configurationSha256,bindings,unitReceipts,counts})`, with exactly those seven keys. `unitReceipts` is the ordered array of `{unitId,actionId,receiptSha256}` sorted by `(unitId,actionId)`; `counts` is exactly `{unitCount,dependencyCount,outputBytes}` and `outputBytes` must be zero. Generic-evidence `bindings.frontendReceiptSha256` is this aggregate digest. CPU, wall-time, peak-memory, and other varying measurements may be retained only in a non-evidence runner log excluded from every canonical file, digest, identity, and replay comparison; runner enforcement still applies.

For each macro definition, hash the exact descriptor `H("decomp-thing/generic-template/macro-definition/v1", {builtin,form,parameters,variadic,variadicForm,replacementTokens})`. `builtin` is a boolean from `MacroInfo::isBuiltinMacro`; `form` is `object` or `function`; `parameters` is null for object-like macros or the ordered exact `MacroInfo::params()` identifier spellings for function-like macros; `variadic` is a boolean; `variadicForm` is `none`, `c99`, or `gnu`; `replacementTokens` is the ordered `{kind,spelling}` token array, empty for a special builtin without a fixed body. V1 rejects GNU named variadic macros as an unsupported language extension. Initial macro rows are `{name,definitionSha256}` sorted by macro-name UTF-8 bytes. Define events carry this `definitionSha256`; undef events carry null. The macro event shape is exactly `{kind,name,definitionSha256,origin,path,line,byteOffset,includeDepth}`. Include events have exactly `{kind,requested,resolvedPath,resolvedSha256,line,byteOffset,includeDepth}`; `kind` is `include`, `include-next`, or `import`, and events preserve Preprocessor callback order. `origin` is exactly `source`, `command-line`, or `builtin`; source macro events require closure-relative `path`, one-based `line`, and zero-based `byteOffset`, while command-line/builtin events require all three to be null. Include events require a non-null authenticated closure-relative `resolvedPath` and `resolvedSha256`, with one-based source line, zero-based byte offset, and include depth. Thus object-like `#define F x`, function-like `#define F() x`, parameter order, and C99 variadic state have different hashes even if replacement tokens match.

`semanticContextSha256 = H("decomp-thing/generic-template/semantic-context/v1", {languageOptions,targetTriple,sourceDateEpoch,predefinedMacroDigest,macroEvents,includeEvents,pchModuleDigests})`. `predefinedMacroDigest = H("decomp-thing/generic-template/predefines/v1", sortedRows)` using the macro rows above. A define's `definitionSha256` replaces the former replacement-token-only digest. `sourceDateEpoch` is null when the authenticated build action leaves `SOURCE_DATE_EPOCH` unset; otherwise it is the exact canonical decimal value passed unchanged to the frontend. A present value must match `0|[1-9][0-9]*` and fit signed 64-bit. No host fallback or adapter-selected default is allowed. V1 rejects any definition or expansion of `__DATE__`, `__TIME__`, or `__TIMESTAMP__`; tests cover direct use, macro indirection, and token pasting. In addition, v1 rejects `-march=native`, `-mcpu=native`, `-mtune=native`, `-target-cpu=native`, and their separated spellings in the original argv or authenticated response-file-expanded driver input. The effective target triple, CPU, and feature set must equal the registered profile. No host CPU probe is accepted.

Reserve the mandatory envelopes before retaining AST rows. First construct the complete required generic-evidence envelope and its empty `genericTemplates` observation-v3/truth-v4 shard projections with validated bindings, all ordered unit receipts, empty entity/edge arrays, and zero-filled count maps; also reserve the empty full-run index projection when that output is required. Let `B0` be the exact aggregate incremental serialized-byte delta across those complete artifacts relative to the corresponding ordinary-only artifacts. This includes repeated unit/binding/count-map fields, each artifact's fixed envelope, field names, delimiters, and the index shell. Let `remainingShardBytes = perShard.serializedBytes - alreadySerializedShardBytes` and `remainingRunBytes = wholeRun.serializedBytes - alreadySerializedRunBytes`; compute `genericBudget = min(64 MiB, remainingShardBytes, remainingRunBytes)`. ### 3. Type and template-argument canonicalization

The supported argument kinds remain `type`, `integral`, `template`, and nested `pack`. A `type` argument is context-sensitive: in `partialPatternArguments` it may contain a representable dependent `templateParameter` type; in instantiated `primaryActuals`, `partialDeducedArguments`, `functionActuals`, and written actuals, a dependent/unresolved type or value is `unsupported` with reason `unresolved-dependent-actual`. Thus `Box<T*>` is representable as a partial pattern, while an unresolved actual is not. `Box<int*>` is a concrete actual. A dependent non-type expression such as `N + 1`, an unexpanded pack expansion, or an unresolved template name remains unsupported; do not collapse all dependent pattern types into unsupported actuals.

Before selecting any `TypeDescriptor` variant, normalize a `QualType` in this exact order: (1) call `getCanonicalType()`; (2) call `getSplitUnqualifiedType()` on that canonical type; (3) emit qualifiers from the returned `Qualifiers` before dispatch, in the sorted subset of `const`, `volatile`, `restrict`; if any other qualifier bit is present, mark the descriptor unsupported; (4) select the variant using only the returned canonical unqualified `Type*`; and (5) recursively apply this same sequence to child `QualType`s. Typedef/`typeof` sugar is deliberately erased before variant selection. `RecordType` backed by a `ClassTemplateSpecializationDecl` maps to `templateSpecialization` using direct Clang declaration pointers and typed template arguments; an ordinary record/enum maps to its record/enum variant. No `getAsString()` or `getSingleStepDesugaredType()` output selects identity. An unsupported qualifier/type does not fall back to the source spelling.

Examples: `using Count = const int;` and `const int` both normalize to `{kind:"builtin",name:<Clang BuiltinType::Kind for int>,qualifiers:["const"]}`; `volatile int*` becomes a pointer with empty outer qualifiers and a volatile builtin pointee; `template<class T> struct Box<T*>` records a pointer whose pointee is `{kind:"templateParameter",qualifiers:[],depth:0,index:0}`; and `Box<int*>` records a specialization descriptor whose actual type argument is a pointer to `int`. Qualifier arrays on every descriptor variant are exactly the CVR subset above; `atomic`, address-space, Objective-C, GC, and unaligned qualifiers are unsupported in v1.

Candidate/reference remapping is also exact. In candidate preimages, replace every `declPhysicalId` by `referenceAnchor(target)`, where the target is obtained from the already-held direct AST pointer, reduced to its canonical redeclaration group's `canonicalAnchor`. Replace `templatePhysicalId` in a template argument by the referenced template's `canonicalAnchor`. Replace both `specializationPhysicalId` and `templatePhysicalId` in a `templateSpecialization` descriptor by the exact referenced specialization/template canonical anchors. No physical ID or pointer value occurs in candidate JSON, and no name lookup is permitted. If any target is outside the same authenticated action or has no canonical source anchor, withhold the candidate.

`languageMode` is one exact JSON object in candidate and semantic-context preimages: `{standard:"c++14",standardVersion:201402,extensions:[],modules:false,exceptions:<boolean>,rtti:<boolean>,charSignedness:"signed"|"unsigned",wcharWidth:<positive integer>}`. V1 rejects another standard, a non-empty extension set, or modules. `exceptions` and `rtti` are captured from the effective `LangOptions`, not defaulted by the adapter; `charSignedness` and `wcharWidth` come from the effective target. This object replaces the prior undefined `languageMode` shorthand.

For any unsupported argument/type tagged `{kind:"unsupported",clangKind,rawSha256}`, `rawSha256` is nullable. When Clang supplies a contiguous authenticated spelling token range, find its token end with the pinned Clang lexer and set `rawSha256 = SHA-256(exact original source bytes [beginOffset,endOffset))`, including intervening whitespace/comments but without macro expansion or text normalization. The range must map to one file in the authenticated closure. If no such range exists, set null and add `missing-source-anchor`; never hash a pretty-printed type, mangled name, pointer, or formatted diagnostic as raw content. The exact `clangKind` is the pinned Clang 18.1.3 enum spelling.

`entity.specializationKind` is null for `primary-template`, `partial-specialization`, and `supporting-declaration`. For a full explicit specialization it is `explicit-specialization`. For a concrete class specialization it is copied from `ClassTemplateSpecializationDecl::getSpecializationKind()`; for a function specialization it is copied from its `FunctionTemplateSpecializationInfo`. Member-specialization kind is carried only on the separate `member-specialization` edge from `MemberSpecializationInfo::getTemplateSpecializationKind()`. Edge-kind mapping is: `templated-declaration`, `redeclares`, and `specializes-primary` have null specialization kind; `instantiates-primary`, `instantiates-partial`, and `instantiates-function-template` use the matching class/function specialization API value; `member-specialization` uses its own member API value; `explicit-specializes` is exactly `explicit-specialization`. The class partial pattern remains `partialPatternArguments`; its dependent typed pattern is not an instantiated actual.

Observation-v3 is the v2 observation shard schema plus one required `genericTemplates` object. The existing root `schemaVersion`, `oracle`, `shard`, `counts`, `emitted`, and `nonEmitted` fields keep their v2 meanings and exact old members; root function/RVA counts remain unchanged. The collision population is broader than `genericTemplates.entities`. Before resolving any generic candidate, #1467/#1468's full-run pass must include every bounded ordinary emitted-definition anchor claim exposed by an additive raw-input/rederivation interface, as well as every anchor-bearing #1467 `sourceEntities` row and all generic frontend rows. If a bucket has multiple claimants, all generic rows in it remain represented but ambiguous; if an ordinary claim lacks any field needed to prove its bucket, the full-run pass fails closed and publishes no resolved generic identities. Root v2 `counts` is not reused for these facts.
